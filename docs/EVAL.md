# 평가 방법론 — 전사(STT: →일본어) / 번역(MT: →한국어)

이 문서는 STT/번역 파이프라인의 출력을 채점하는 절차를 정의한다. 아래 절차를 그대로 따르면
누가/어떤 모델이 채점하든 동일한 결과가 나와야 한다.

## 1. 평가 데이터 형식

세그먼트(발화 단위) 1건당 아래 3개 필드로 구성된 참조 데이터셋을 사용한다.

| 필드 | 설명 |
|---|---|
| `audio` | 오디오 클립 |
| `ja_ref` | 정답 일본어 전사 |
| `ko_ref` | 정답 한국어 번역 |

데이터셋 파일에는 버전/날짜를 붙인다 (예: `eval_set_2026-08-18.jsonl`). 모델/설정을 바꿔 재평가할
때는 반드시 동일 파일을 재사용한다.

세그먼트는 다음 두 그룹으로 나눠 태깅해둔다: `normal`(또박또박한 발화), `hard`(필러/반복 다수,
웃음, 겹쳐 말하기, 은어/축약어, 고유명사 포함 발화). 최종 리포트는 그룹별로도 나눠 집계한다.

## 2. 전사(STT) 평가

### 2.1 텍스트 정규화 (채점 전 필수 전처리)

`ja_ref`와 모델 출력(하이포시스) 양쪽에 동일하게 적용한다.

1. 유니코드 NFKC 정규화 (전각/반각 통일).
2. 다음 구두점 제거: `、。！？「」『』・…` 및 공백.
3. 그 외 문자(가나/한자/영숫자)는 그대로 유지 — 한자/가나 표기 차이는 오류로 채점한다.

### 2.2 CER (Character Error Rate)

정규화된 `ja_ref`와 정규화된 출력 사이 문자 단위 편집거리로 계산한다.

```
CER = (S + D + I) / N
```
- S: 치환, D: 삭제, I: 삽입 (Levenshtein 정렬 기준)
- N: `ja_ref`의 총 글자 수

도구: `jiwer.cer(ja_ref_normalized, hypothesis_normalized)`.

**분리 집계**:
- provisional 하이포시스와 final 하이포시스의 CER을 각각 따로 계산한다 (하나로 합치지 않는다).
- `normal` / `hard` 그룹별로 각각 따로 계산한다.
- glossary 등록 고유명사가 포함된 세그먼트만 모아 별도 CER("고유명사 CER")을 계산한다.

### 2.3 오류 카테고리 태깅

정렬(alignment) 결과에서 오류가 발생한 구간마다 아래 카테고리 중 하나를 부여한다. 한 세그먼트에
여러 오류가 있으면 각각 별도로 태깅한다.

| 카테고리 | 판정 기준 |
|---|---|
| 동음이의 치환 | 오인식된 단어가 정답과 발음이 유사하지만 다른 실재 단어이고, 의미가 바뀜 |
| 완전 붕괴 | 오인식 구간이 문법적으로 성립하지 않는 문자열 |
| 환각 | `ja_ref`에 대응하는 발화가 없는데 텍스트가 생성됨 (특히 세그먼트 앞/뒤 무음 구간) |
| 세그먼트 절단 | 문장/단어가 세그먼트 경계에서 중간에 끊김 |
| 표기 오타 | 발음은 정답과 일치하지만 가나/한자 등 표기만 틀림 |
| 고유명사 오인식 | glossary 등록 대상 고유명사가 다른 단어로 대체되거나 환각됨 |

### 2.4 심각도 등급

| 등급 | 기준 |
|---|---|
| S1 | 세그먼트의 핵심 의미가 바뀜 |
| S2 | 의미는 문맥상 유추 가능하나 읽기에 지장이 있음 |
| S3 | 의미 전달에 지장 없음 (표기 수준) |

**리포트 지표**: 세그먼트 100개당 S1 건수(핵심 KPI), 카테고리별 건수 분포, CER(§2.2 분리 기준별).

## 3. 번역(MT) 평가

### 3.1 자동 지표: chrF++

`ko_ref`와 모델 출력(final 번역만 대상) 사이 chrF++를 계산한다. provisional 번역에는 적용하지
않는다 (§3.3 참조).

도구: `sacrebleu.corpus_chrf(hypotheses, [references], word_order=2)` (`word_order=2` = chrF++).

토큰화/형태소 분석 전처리는 하지 않는다 (chrF++는 문자 n-gram 기반이므로 불필요).

`normal` / `hard` 그룹별로 각각 따로 집계한다.

### 3.2 Final(완성 문장) 번역 — 사람 채점표

세그먼트 1건당 아래 4개 항목을 각각 1~5점으로 채점한다.

| 항목 | 1점 | 3점 | 5점 |
|---|---|---|---|
| 의미 충실도 | `ko_ref`와 다른 뜻 | 대체로 맞으나 일부 누락/과장 | `ko_ref`와 의미 일치 |
| 자연스러움 | 직역투/비문 | 어색하지만 이해 가능 | 그대로 자막으로 쓸 수 있는 수준 |
| 존댓말/반말 일치 | 원문의 격식 수준과 불일치 | 부분적으로 일치 | 원문과 동일한 격식 수준 유지 |
| 스크립트 순수성 | 한글이 아닌 문자(영어/키릴/한자 등)가 출력에 존재 | — | 한글 + 숫자 + 기본 문장부호만 존재 |

**S1 자동 실패 조건** (위 점수와 별개로 카운트, 하나라도 해당하면 해당 세그먼트를 S1으로 기록):
- 라틴 문자(A-Z, a-z)가 출력에 포함됨
- glossary에 없는 고유명사가 임의로 생성됨
- `ja_ref`에 없는 내용이 출력에 추가됨(창작)
- `ja_ref`에 있는 내용이 출력에서 누락됨

### 3.3 Provisional(진행 중) 번역 — 이진 채점

- `ja_ref`(또는 해당 시점까지의 부분 발화)에 등장하는 단어가 빠짐없이 어떤 형태로든 한국어로
  나왔으면 **pass**, 하나라도 누락됐으면 **fail**.
- fluency/자연스러움은 채점하지 않는다.
- 리포트 지표: pass율(%).

### 3.4 오류 원인 분리

Final 번역이 S1으로 판정된 세그먼트마다 다음을 확인해 `원인` 열에 기록한다:

1. 해당 세그먼트의 STT 출력이 `ja_ref`와 일치하는가?
   - 일치 → 원인: **번역**
   - 불일치 → `ja_ref`를 번역기에 직접 입력해 동일 문제가 재현되는지 재확인
     - 재현됨 → 원인: **번역**
     - 재현 안 됨 → 원인: **STT 전파**

## 4. 평가 절차

1. §1 형식으로 참조 데이터셋 준비, 버전 파일명 부여.
2. 현재 `backend/config.py` 설정으로 데이터셋 전체를 파이프라인에 통과시켜 provisional/final
   STT·번역 결과를 각각 기록.
3. §2, §3의 절차대로 채점.
4. 결과를 §5 형식으로 리포트.
5. 모델/프롬프트/config 변경 시 1의 동일 데이터셋으로 2~4를 반복해 이전 리포트와 비교.

## 5. 리포트 형식

평가 1회당 아래 표를 산출한다.

**STT**

| 그룹 | provisional CER | final CER | 고유명사 CER | S1 건수/100세그먼트 |
|---|---|---|---|---|
| normal | | | | |
| hard | | | | |
| 전체 | | | | |

카테고리별 오류 건수 표(§2.3 6개 카테고리 x 그룹별 건수)를 별도로 첨부.

**번역**

| 그룹 | final chrF++ | 의미 충실도(평균) | 자연스러움(평균) | 존댓말 일치(평균) | 스크립트 순수성(평균) | S1 건수/100세그먼트 | provisional pass율 |
|---|---|---|---|---|---|---|---|
| normal | | | | | | | |
| hard | | | | | | | |
| 전체 | | | | | | | |

S1 세그먼트 목록(세그먼트 ID, 원인: 번역/STT 전파)을 별도로 첨부.
