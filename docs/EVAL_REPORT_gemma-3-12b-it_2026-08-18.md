# 평가 리포트 — Gemma-3-12b-it 번역 모델 (2026-08-18)

방법론은 `docs/EVAL.md` §3.2/§3.4 기준. 데이터셋·STT 가설(`hyp_ja`)은 `docs/EVAL_REPORT_2026-08-18.md`
(베이스라인, Qwen2.5-7B-Instruct)와 동일한 120클립(단일 화자, `data/wav` 5개 카테고리)을 재사용했다
— `data/bench_gemma-3-12b-it.jsonl`의 `hyp_ja`는 "이전 CPU Whisper 평가에서 나온 STT 가설(모든 모델
벤치마크에서 재사용된 동일 값)"이므로, STT 쪽 변수는 완전히 통제되고 번역 모델(Qwen2.5-7B-Instruct
Q4_K_M → Gemma-3-12b-it)만 바뀐 순수 A/B 비교다.

`hyp_ko`(STT 가설을 입력으로 한 실제 파이프라인 출력)를 채점 대상으로 삼았고, `hyp_ko_from_ref`
(정답 전사를 직접 입력한 결과)는 §3.4 원인 분리에만 사용했다. 채점은 베이스라인과 동일한 엄격도
(애매하면 S1로 판정)를 유지했다.

## 1. 자동 지표 — chrF++

`sacrebleu.corpus_chrf(hyp_ko, [ko_ref], word_order=2)`로 직접 재계산.

| 그룹 | n | chrF++ (hyp_ja→hyp_ko, 실제 파이프라인) | chrF++ (ja_ref→hyp_ko_from_ref, STT 오류 배제) |
|---|---|---|---|
| normal | 94 | 23.20 | 30.04 |
| hard | 26 | 22.30 | 26.05 |
| 전체 | 120 | **22.86** | **28.69** |

베이스라인(Qwen2.5-7B, 동일 STT 가설 기준) chrF++는 전체 17.3(정답 전사 직접 번역 시 24.25)이었다.
Gemma-3-12b-it은 두 조건 모두에서 **약 4.4~5.6점 높다** — 자동 지표상 개선은 사람 채점 라운드
이전에 이미 확인된 결과와 일치한다.

## 2. 사람 채점 — `docs/EVAL.md` §3.2

전 120세그먼트를 Claude가 직접 `hyp_ko` vs `ko_ref`로 채점 (`data/bench_gemma-3-12b-it_graded.jsonl`).

| 그룹 | n | 의미충실도 | 자연스러움 | 존댓말일치 | 스크립트순수성 | S1율 |
|---|---|---|---|---|---|---|
| normal | 94 | 2.78 | 3.34 | 3.09 | 5.00 | 51.1% |
| hard | 26 | 3.88 | 4.38 | 3.69 | 5.00 | 15.4% |
| 전체 | 120 | **3.02** | **3.57** | **3.22** | **5.00** | **43.3%** |

라틴 문자 유출은 0건 — grammar 제약이 여전히 의도대로 작동. `hard` 그룹이 `normal`보다 전 지표에서
낫게 나오는 패턴은 베이스라인과 동일 방향(표본 26개의 구성 편향으로 추정, 여전히 재검토 필요).

## 3. 원인 분리 — STT 전파 vs 번역 자체 (§3.4)

S1 52건을 세그먼트 단위로 원인 분리:

| 원인 | 건수 | 비율 |
|---|---|---|
| STT 전파 | 43 | 82.7% |
| 번역 자체 | 9 | 17.3% |

코퍼스 레벨 교차검증(§1의 두 chrF++ 열): STT 오류를 완전히 제거해도(정답 전사를 직접 번역해도)
chrF++가 28.69에 그쳐 여전히 "잘 되는 MT" 기준(40~60+)에 못 미친다 — 번역 엔진 자체의 한계도
분명히 남아있지만, S1 카운트 기준으로는(82.7% STT 전파) 베이스라인(69% STT 전파)보다 **STT가
차지하는 비중이 더 커졌다**. 즉 Gemma로 바꾼 뒤에는 번역 엔진 자체가 스스로 만들어내는 실패가
줄고, 남은 실패의 대부분이 (동일한 채로 유지된) STT 오류의 전파에 기인한다.

## 4. 베이스라인(Qwen2.5-7B-Instruct) 대비 비교

| 지표 | 베이스라인 (Qwen2.5-7B) | Gemma-3-12b-it | 변화 |
|---|---|---|---|
| 의미충실도 | 2.72 | 3.02 | **+0.30** |
| 자연스러움 | 2.85 | 3.57 | **+0.72** |
| 존댓말일치 | 2.74 | 3.22 | **+0.48** |
| S1율 | 50.8% | 43.3% | **-7.5%p** |
| chrF++ (전체, hyp_ko) | 17.3 | 22.86 | +5.56 |
| chrF++ (전체, ja_ref 직접번역) | 24.25 | 28.69 | +4.44 |
| S1 원인 중 STT 전파 비율 | 69% | 82.7% | +13.7%p (번역 자체 실패 비중 감소) |

**전 항목에서 개선.** 특히 자연스러움(+0.72)과 S1율(-7.5%p)의 개선폭이 크다. STT가 완전히 통제된
동일 조건에서 번역 모델만 교체했으므로, 이 개선은 순수하게 Gemma-3-12b-it의 번역 품질 우위로
귀속시킬 수 있다.

### 베이스라인 반복 오류 패턴과의 대조 (`docs/EVAL_REPORT_2026-08-18.md` §4)

- **패턴 A(STT 무출력, `7112` 영상 저음량)** — STT가 동일하므로 그대로 재현(23건). 이건 번역
  모델 교체로 해결될 수 없는, STT/오디오 전처리 쪽 이슈로 원래 계획대로 남아있다.
- **패턴 B(고유명사 동음이의 오인식 전파)** — **동일 사례에서 그대로 재현**됨:
  - マッターホルン(마터호른) → Gemma도 "마타가 눈이 올 거예요?"로 오역 (STT가
    `まったー降るんですか`로 깨진 걸 그대로 따라감 — Qwen도 같은 유형으로 실패)
  - 白馬岳(하쿠바다케) → "하얀 말만 올라오셨다는 분" (STT `白馬だけ`를 문자 그대로 직역)
  - 千恵子先生(치에코 선생님) → "츠코 선생님" (Qwen은 "체코 선생님"이었던 것과 같은 계열의
    실패, 다른 방식으로 틀림)
  → 두 원인 모두 STT 단계의 동음이의 오인식이 원흉이며, glossary가 비어있는 현재 상태에서는
  번역 모델을 바꿔도 해결되지 않는다. **`glossary.json`을 채우는 조치(베이스라인 리포트 §5-B)가
  여전히 유효하고 시급하다.**
- **패턴 C(번역기 자체 오역)** — 빈도는 줄었으나(9건, 베이스라인 19건) 완전히 사라지지는 않음.
  새로 관찰된 사례:
  - 流れ星(별똥별) → "나래별" (STT는 정확했는데 존재하지 않는 단어를 생성)
  - 米田(요네다) → "미다"/"요미타" (같은 이름이 두 세그먼트에서 다르게, 둘 다 틀리게 나옴 —
    Qwen 때와는 다른 어휘지만 "고유명사를 반복적으로 못 맞춘다"는 동일 유형의 체계적 약점)
  - こんにちは/こんばんは 인사 말장난을 번역 못 하고 "녕안하세요"라는 존재하지 않는 단어를 생성
  - 스위스 지명이 잔뜩 나열된 긴 문장을 "이건 글라스예요"로 통째로 축약(주요 내용 누락)
  → 빈도는 확실히 줄었지만, "반복적으로 특정 유형에서 실패한다"는 베이스라인의 핵심 관찰
  자체는 여전히 유효.
- **패턴 D(조기 종결)** — 이번 평가도 사람이 이미 자른 클립을 쓰므로 여전히 측정 범위 밖.

## 5. 결론 — 프로덕션 채택 여부

**Gemma-3-12b-it로 교체할 것을 권고한다.** 근거:

1. 사람 채점 4개 항목 전부, chrF++ 두 조건 모두에서 Qwen2.5-7B-Instruct 대비 일관되게 개선됐다
   (S1율 50.8% → 43.3%, 의미충실도 +0.30, 자연스러움 +0.72, 존댓말일치 +0.48).
2. S1 실패의 원인 구성이 "번역 자체 문제"에서 "STT 전파"로 더 쏠렸다(31%→17.3%) — 이는 번역
   모델 자체의 신뢰도가 높아졌다는 뜻이며, 남은 문제의 상당수는 이미 계획돼 있던 별도 작업
   (§5-A 오디오 게인 정규화, §5-B glossary 채우기)으로 해결 가능한 영역으로 이동했다.
3. 라틴 문자 유출 없음(스크립트 순수성 5.00 유지) — grammar 제약이 모델을 바꿔도 안정적으로
   작동함을 재확인.

다만 **"완벽한 번역"(1차 목표)에는 아직 한참 못 미친다** — S1율 43.3%는 여전히 절반에 가까운
세그먼트가 핵심 의미 파손을 겪는다는 뜻이고, STT가 완벽해도(§1의 ja_ref 직접번역 chrF++ 28.69)
"잘 되는 MT" 기준(40~60+)에 크게 못 미친다. 모델 교체는 필요조건 중 하나를 만족시켰을 뿐,
다음 두 가지가 여전히 최우선 과제로 남는다:
- STT 쪽 개선(패턴 A 오디오 게인 정규화, 특히 고유명사 hotwords) — 이번 라운드에서 S1의 82.7%가
  STT 전파로 확인됐으므로, 번역 모델을 바꾼 지금은 오히려 STT 개선의 레버리지가 더 커졌다.
- glossary.json 재도입 — マッターホルン/白馬岳/千恵子 같은 반복 사례가 모델을 바꿔도 그대로
  재현되는 것은 정확히 이 인프라가 해결하도록 설계된 문제다.

## 6. 실사용 로그 기반 추가 발견 (2026-08-19, 이 평가셋 밖)

프로덕션 전환 후 실제 유튜브 라이브로 확인하며 나온, 위 §1~5의 120세그먼트 평가셋에는 없는
새 패턴. 정식 재평가 라운드는 아니고 실사용 스팟체크 기록.

- **번역 결과에 문법적으로 성립하지 않는 어미가 붙는 경우**: `忙し、暇な時間は作るもんなんだ!`
  → "바빠, 짬은 내야지 뭐**니까**!" — "뭐니까"는 정상적인 한국어 표현이 아님. 재현 조건 불명,
  모델이 드물게 만들어내는 것으로 보이는 글리치. 원인 조사 필요(다음에 비슷한 사례가 더
  쌓이면 착수).
- **STT 오인식이 번역 의미를 반전시키는 사례 추가 확인**: `だだけてるから`(STT 추정 오인식,
  원래는 `だらけてるから`=늘어져 있으니까/게으르니까)가 "**뻐기고** 있는 거라서"(으스대다,
  정반대에 가까운 의미)로 번역됨 — §3의 "STT 전파" 원인 카테고리와 같은 유형. STT 게인
  정규화/모델 개선(§5 결론의 최우선 과제)이 여전히 유효한 근거.
- **`_FALSE_FRIEND_NOTE` 추가로 확인된 개선**: やばい가 발음이 비슷한 무관한 한국어 단어
  "야바위"(사기/야바위판)로 오역되는 사례를 실사용 중 확인 → `llama_server_engine.py`에
  false-friend 방지 지침 추가로 해결 확인(재현 테스트로 검증). 같은 세션에서 문장 끝
  `嘘`(우소)가 "농담이야"류 관용구가 아니라 "~라는 게 거짓말이다"로 직역되는 문제도 같은
  지침으로 같이 해결.
