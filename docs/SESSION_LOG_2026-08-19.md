# 세션 기록 — 2026-08-19 (번역 품질 개선, 시행착오 일지용 원본)

`batch1-instrumentation` 브랜치에서 GPU 실측 검증을 시작한 이후 하루 동안 있었던 문제 발견 →
시도 → 결과를 시간 순으로 정리. 나중에 일지 작성 시 참고용 원본 기록이며, 결론만 필요하면
`CLAUDE.md`의 "STT / translation engine" 절과 [[project_2026-08-19_quality-milestone]] 참고.

## 1. 팝업 자막 순서 꼬임

- **문제**: 실캡처 녹화 영상을 보니 최종 번역 문장이 순차적으로 쌓이다가 이따금 순서가
  뒤바뀐 채로 확정되는 현상 발견.
- **원인**: `popup.js`의 `restoreHistory()`가 비동기로 과거 로그를 불러오는 동안, 실시간
  `TRANSCRIPT_EVENT`가 먼저 도착해 DOM에 먼저 append되는 레이스.
- **조치**: `restoring` 플래그 + `pendingEvents` 버퍼를 두어, 히스토리 복원이 끝난 뒤 버퍼링된
  이벤트를 순서대로 replay. (해결됨, 이후 재발 없음)

## 2. "끝까지 시청해주셔서 감사합니다" 환각 — 최초 발견

- **문제**: 실제 발화도, 음량도 없는 순간에 해당 문구가 번역되어 나타남.
- **1차 조치(정규식)**: `_HALLUCINATED_OUTRO_RE`/`_BRACKETED_HALLUCINATION_RE`로 패턴 매칭 시도.
  라벨링된 실데이터 중 40%가 이 계열이었는데도 변형(視聴して/くださって/공백/本当に 등)을
  다 못 잡음.
- **사용자 피드백**: "설마 정규식으로 잡으려던건 아니겠지?" — 정규식 접근 자체를 명시적으로
  금지. "비효율적인 발상"이라는 이유.
- **2차 조치**: 정규식 완전 삭제, Whisper 자체 신뢰도 신호(`no_speech_prob`, `avg_logprob`)
  기반 2단계 임계값으로 전환.

## 3. RMS 오디오 에너지 게이트 추가

- Whisper의 자체 확률만 믿지 말고, 실제 오디오 에너지(RMS)가 무음 수준이면 아예 STT를
  호출하지 않도록 `AUDIO_RMS_SILENCE_FLOOR = 0.006` 추가. partial/final 양쪽에 적용.

## 4. 신뢰확률 시각화 + 클릭-투-플래그 라벨링

- 팝업에 `audio_rms`/`no_speech_prob`/`avg_logprob`를 막대그래프로 표시(백엔드 임계값과
  색상 매칭 — 실제 필터링 로직과는 별개, 디버깅 가시성 목적).
- 완성 문장 클릭 → 분홍 배경으로 "오역" 표시, 재클릭으로 해제. `FLAG_SEGMENT` 메시지가
  WS를 통해 백엔드로 전달되어 `data/flagged_segments.jsonl`에 누적 저장.
- 이 라벨 데이터가 이후 모든 임계값 튜닝의 근거가 됨.

## 5. no_speech_prob 임계값 튜닝

- 최초 `WHISPER_NO_SPEECH_HARD_THRESHOLD = 0.9` — 실측 결과 0.898/0.824 같은 실제 환각
  사례를 못 잡음 → **0.75로 하향**.
- 그래도 0.7495, 0.578 같은 사례는 놓침 — 문제는 이 값들이 **진짜 발화의 no_speech_prob
  분포(0.64~0.73)와 겹친다는 것**. 확률 신호 단독으로는 구조적 한계에 도달.
  → 이 한계가 이후 임베딩 유사도 게이트 도입의 직접적 동기가 됨.

## 6. 문장 경계 / STT 모델 / 부분번역 — 사용자 지시 3건 동시 반영

사용자 지시(요약): "medium을 더 이상 신용 못 하겠다. large로 바꿔라. 부분 번역 기능은
주석처리해서 deprecated 해라. 완전한 문장만 번역하고, 문장 완성 전까지는 전사만 해라."

- `sentence_completion.py::has_strong_sentence_boundary`: 이전엔 버퍼 **꼬리(tail)만** 종결
  부호(。！？)를 검사 → 말이 빠른 화자가 한 사이클 안에 여러 문장을 말하면 앞쪽 종결부호가
  꼬리 밖으로 밀려나 못 잡히고, 결국 `MAX_UTTERANCE_SECONDS`로 강제 절단되는 문제. → **버퍼
  전체**를 먼저 스캔하도록 수정.
- STT 모델 `medium` → `large-v3` (CTranslate2, int8_float16).
- `audio_session.py::_emit_partial`의 실시간 부분 번역 호출부를 주석 처리(삭제 아님).
  partial 이벤트는 이제 일본어 전사만 담고 `translation: ""`.

## 7. 배경음악 환각 대응 — 뮤직 게이트 시도 후 즉시 폐기

- **가설**: 배경음악이 환각을 유발하므로 VAD 이전 단에서 "이건 발화가 아니라 음악"이라고
  판단해 걸러내면 좋겠다.
- **선택한 접근**(사용자 승인: "가벼운 음악/발화 판별 특징 기반"): Scheirer/Slaney 스타일
  4Hz 변조 주기성 검출(`backend/music_gate.py`). 초기 밴드합-비율 방식은 화음
  비트(beating) 때문에 오탐 → 좁은 밴드 피크-프로미넌스 방식으로 변경, 합성 신호로 검증.
- **결과**: 실캡처에 적용하자마자 **실제 발화 자체를 놓침** ("이번엔 음성 자체를 놓치네").
  번역 정확도도 함께 하락 ("번역 정확도도 내려갔어. 더 별로인거 같아.").
- **조치**: 원칙("실제 발화를 희생하면서까지 환각을 줄이지 않는다")에 따라 추가 튜닝 없이
  즉시 `MUSIC_GATE_ENABLED = False`로 비활성화. 코드는 남겨두되 재활성화 전 실캡처 오디오로
  재보정이 선행 조건이라고 주석에 명시.
- **연쇄 문제**: 이후 발견된 "최종 문장의 29%가 빈 문자열" 회귀를 `backend_run.log` grep으로
  추적한 결과, 뮤직 게이트가 켜져 있던 구간에서 실제 발화가 짧고 조용한 버퍼로 잘려나가
  RMS/no_speech 게이트에 연쇄적으로 걸린 것이 원인으로 확인. 게이트 비활성화로 해결.

## 8. fallback 로직 버그 — 걸러낸 환각이 되살아남

- **문제**: final STT 패스가 저신뢰/환각으로 명시적으로 걸러냈는데도(`dropped_low_confidence`),
  "final이 비었으면 last_partial_text로 폴백"하는 로직이 무조건 실행되어 방금 막 걸러낸
  환각 문구가 그대로 부활.
- **조치**: `audio_session.py::_do_finalize`의 폴백 조건을 `if not final_text:` →
  `if not final_text and not dropped_low_confidence:`로 수정.
- **사용자 지시**: "지금은 문제 1에만 집중해. ㅋㅋㅋ는 마이너한 이슈야... 새 버그는 문제
  1과 함께 고쳐야겠어." — ㅋㅋㅋ 임의 첨가 이슈는 명시적으로 후순위로 미룸.

## 9. 문헌 조사 → 임베딩 유사도 "Bag of Hallucinations" 게이트

- **사용자 지시**: "일단 코드수정부터 하기 전에 이와 같은 앱이나 연구 중에서 이러한 문제들을
  어떻게 해결했는지 알아보자. 우선 문헌 조사부터 시작해." — 확률 신호 단독의 구조적 한계
  (5번 항목)에 부딪힌 뒤, 바로 코드를 고치지 않고 먼저 유사 사례를 조사.
- **채택한 방법**: Baranski et al. 2025의 "Bag of Hallucinations" 방식 — 알려진 환각 문구
  레퍼런스 집합을 문장 임베딩(`sentence-transformers`,
  `paraphrase-multilingual-MiniLM-L12-v2`)으로 미리 인코딩해두고, STT 결과와의 코사인
  유사도가 임계값(0.78) 이상이면 드롭. 확률 신호를 대체하지 않고 **독립적인 두 번째
  신호**로 병행.
- **구현**: `backend/hallucination_gate.py`(게이트 클래스), `backend/known_hallucinations.json`
  (`data/flagged_segments.jsonl`에서 실제 관찰된 환각 문구 7개 정제).
- **검증**: 실캡처 로그에서 `no_speech_prob=0.162`처럼 확률 신호만으로는 절대 못 잡을 사례를
  임베딩 유사도로 잡아내는 것을 확인 — 설계 의도대로 동작.

## 10. 익스텐션 UI가 계속 접히는 문제 — 세 번의 접근 전환

- **요청**: "지금 익스텐션을 띄운 상태로 창을 조작하면 접히는데 안 접히도록 해줘."
- **1차 시도: `chrome.sidePanel`**. 패널 안의 "Start Capture" 버튼 클릭이
  `activeTab` 권한을 못 받아 `"Extension has not been invoked for the current page"` 에러로
  실패. 원인 규명 과정:
  - 콘솔 로그 계측(`withTimeout` 래퍼) 추가 후 실제 에러 문구 확보.
  - "활성 탭이 devtools 탭 아니냐"는 가설 → 사용자가 유튜브 탭에서 눌렀다고 확인, 기각.
  - `action.onClicked`로 캡처 시작을 옮겨봤지만 동일 에러.
  - `chrome.storage.session` 디버그 플래그를 `action.onClicked` 맨 위에 심어 UI에 노출 →
    "no icon click recorded" 확인 → **`manifest.json`에 `side_panel`이 선언되어 있으면
    Chrome이 아이콘 클릭을 가로채 패널을 직접 열어버려서 `action.onClicked` 자체가 아예
    발동하지 않는다**는 사실을 실증적으로 증명.
  - 중간에 `trigger.html`/`trigger.js`라는 별도의 투명 팝업으로 제스처를 다시 잡아보려는
    시도도 실패 → 결국 삭제.
- **2차: classic `default_popup` + 분리 창**. 클릭 시 팝업 안에서 "Start Capture" →
  성공하면 `chrome.windows.create({type:"popup"})`로 포커스를 잃어도 안 닫히는 별도 창을
  띄우고 팝업 자신은 `window.close()`.
- **사용자 추가 요청**: "익스텐션 버튼을 누르면 바로 창이 열리도록 해줘. 팝업은 필요없어."
  → **3차(최종)**: `manifest.json`에서 `default_popup` 자체를 제거해 `action.onClicked`가
  다시 정상 발동하도록 하고, 그 핸들러 안에서 곧바로 `startCapture(tab.id)` +
  `chrome.windows.create`(이미 열려있으면 포커스만) 수행. 중간 팝업 단계 완전히 제거.

## 11. 볼륨 저하 "수정" → 번역 완전 중단 회귀 (가장 뼈아픈 실수)

- **문제 제보**: "이 익스텐션을 키면 볼륨이 살짝 작아지네?"
- **조치(검증 없이 배포)**: `getUserMedia` 오디오 제약에 `echoCancellation`/
  `autoGainControl`/`noiseSuppression`을 모두 `false`로 명시 — "AGC가 볼륨을 깎는다"는
  그럴듯한 가설만으로 즉시 코드 수정.
- **회귀**: 곧바로 "이번에는 또 못 불러오네", 이어서 **"번역이 전혀 안되고 있어"** 보고.
  `backend_run.log` 확인 결과 거의 모든 세그먼트가 "ご視聴ありがとうございました" 환각으로
  드롭되고 있었음 — AGC를 끄면서 실제 캡처 오디오 레벨 자체가 낮아져 `no_speech_prob`이
  치솟은 것.
- **근본 원인**: `<audio>` 재생 엘리먼트와 STT로 가는 WebAudio 그래프가 **같은
  `MediaStream` 트랙 하나**를 공유하는 구조라, "재생 볼륨만" 고치려던 변경이 STT 입력
  신호까지 동시에 건드림.
- **조치**: 변경 전체 되돌림. 원인·교훈은 [[feedback_verify_pipeline_changes_against_logs]]에
  기록 — 앞으로 오디오 파이프라인 변경은 반드시 `backend_run.log`로 검증 후 완료 보고.
- 볼륨 저하 자체는 아직 미해결 상태로 남음 (재생 경로만 분리해서 게인을 만지는 방법이
  필요 — 다음에 다시 다룰 것).

## 12. 최종 검증 — 품질 마일스톤 확인

- AGC 되돌린 뒤 새로 캡처 시작, 라이브로 함께 지켜봄.
- 처음엔 partial STT 폴링 로그에서 "matched known hallucination" 드롭이 반복되어 우려했으나,
  사용자 확인 결과 **자막은 정상적으로 점점 채워지다 확정되는 정상 흐름**이었고, 드롭된
  것은 버퍼 앞부분(무음/숨소리 등)이었던 것으로 보임 — 실제 문제 아님.
- 노래(가창) 구간도 환각 없이 정상적으로 캡처·번역됨 — 원래 3순위로 미뤄뒀던 음악 환경
  대응이 이번 변경들의 부수 효과로 개선된 것으로 보임.
- **약 30분간 신규 플래그(오역 신고) 0건.** 사용자 확정: "확실히 번역 퀄리티가 많이
  올랐어. 지금까지도 눈에 띄는 오역이 없네. 완벽하진 않지만!"
