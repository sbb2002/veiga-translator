# 프로파일 P1 — 일반 사무용 노트북 (Intel iGPU + i5급)

> 상태: **초기 가설 번들**. 모든 수치·설정은 평가 세션에서 확정한다. 실측 전 품질/지연 수치를 이 문서에 적지 않는다.
> 근거와 전체 평가 계획: `docs/planning/HARDWARE_PROFILES.md` (§2, §3, §4, §8).

## 1. 대상 하드웨어와 최소 사양 (가설)

| 항목 | 최소 | 권장 | 비고 |
|---|---|---|---|
| CPU | Intel i5급 (4코어 이상) | i5 U/H 시리즈 최신 세대 | 가설 |
| GPU | Intel 내장 iGPU (Vulkan 지원) | 동일 | dGPU 없음 |
| RAM | 16GB | 16GB 듀얼채널 | iGPU 가 시스템 RAM 을 공유. 싱글채널이면 비지원 후보 |
| 디스크 | 여유 5GB 이상 | SSD | 모델 파일 약 2.5GB + STT 모델 약 0.6GB + 바이너리 |
| 전원 | AC 전원 연결 | AC 전원, 고성능 모드 | 배터리 모드는 별도 측정 항목 |

미달(싱글채널 RAM, 8GB 등)은 비지원으로 둔다.

## 2. 번들 구성

| 구성 요소 | 값 (초기 가설) | 근거 / 상태 |
|---|---|---|
| STT | whisper.cpp `whisper-server` (Vulkan), `ggml-large-v3-turbo-q5_0.bin` | turbo + q5_0 양자화. 품질 동등성 미확인 (L1) |
| 번역 | llama.cpp `llama-server` (Vulkan), `gemma-3-4b-it-Q4_K_M.gguf`, `-c 2048 -np 1` | 4B 품질 미검증 (L1 비열등성) |
| VAD | silero-vad ONNX (onnxruntime, CPU) | `VAD_BACKEND=onnx`, L1c 동등성 필요 |
| 환각 게이트 | MiniLM ONNX (onnxruntime) | `HALLUCINATION_GATE_BACKEND=onnx`, L1c 동등성 필요 |
| partial 주기 | `PARTIAL_UPDATE_INTERVAL_S = 1.2` | 기본 0.6 에서 완화한 가설 |
| torch | 설치하지 않음 | `backend/requirements-lite.txt` 전제 |

설정 원본: `profiles/p1.yaml`.

## 3. 필요 파일 (저장소에 없음 — 평가 전 준비)

| 경로 | 내용 |
|---|---|
| `llama-server-vulkan/llama-server.exe` (+ DLL) | llama.cpp Vulkan 빌드. 버전 기록 필수 |
| `whisper-server-vulkan/whisper-server.exe` (+ DLL) | whisper.cpp Vulkan 빌드. 버전 기록 필수 |
| `backend/models/google_gemma-3-4b-it-Q4_K_M.gguf` | 번역 모델 |
| `backend/models/ggml-large-v3-turbo-q5_0.bin` | STT 모델 |
| `profiles/` 의 CPU 대안 | 미작성. 비교 측정 시 `-ngl 0` 및 CPU 빌드용 exe 경로로 임시 오버라이드 |

## 4. 설치 의존성

```
pip install -r backend/requirements-lite.txt
```

torch / transformers / sentence-transformers 를 설치하지 않는다. `STT_ENGINE=qwen3-asr` 은 이 세트에서 동작하지 않는다.

## 5. 실행 방법

PowerShell:

```
$env:LT_PROFILE = "p1"
start.cmd
```

백엔드만 직접 띄울 때:

```
$env:LT_PROFILE = "p1"
uvicorn backend.main:app --port 8000
```

측정 시에는 `$env:LT_PROFILE_OVERLAYS = "_measure"` 를 함께 준다(타임아웃 폴백 해제, HARDWARE_PROFILES.md §8.3 L3).

런처는 `launch-args llama p1` / `launch-args whisper p1` 결과로 두 서버를 띄운다.

## 6. 평가 시 확인 항목

- **Vulkan vs CPU 비교 (필수)**: llama.cpp 는 `-ngl 999`(Vulkan) 와 `-ngl 0`(CPU) 을, whisper.cpp 는 Vulkan 빌드와 CPU 빌드를 같은 모델·같은 입력으로 측정한다. Intel iGPU 에서 Vulkan 이 CPU 보다 느릴 수 있다는 vendor 보고가 있다.
- **STT 와 번역 직렬 합산**: 두 서버가 같은 iGPU/RAM 을 공유하므로 동시 가동 상태에서 RTF 와 tok/s 를 함께 잰다.
- **대역폭 추정 검증**: 4B Q4(약 2.5GB) 의 generation tok/s 를 측정해 이론 상한 16~24 tok/s 와 비교한다(추정치).
- **L1 품질**: gemma-3-4b-it 번역 chrF++ 와 정성 평가를 기준선(12B)과 페어드 비교. 불합격이면 P1 탈락.
- **L3 지연 드리프트**: 말 끝→한국어 final 지연의 p50/p95 와 경과 시간 대비 기울기. 대기열 증가 여부.
- **서멀/전원**: AC 와 배터리 두 조건, 10분 지속 부하에서 클럭 저하 기록.
- **RAM 피크**: iGPU 공유 메모리 포함 시스템 RAM 피크 기록.
- **결과 기록**: `docs/eval/HW_PROFILES_RESULTS.md` 의 P1 행, `측정환경: DEV(4080 SUPER) | 추정` 표기 규칙 준수. 이 개발기는 P1 과 다른 하드웨어이므로 **P1 의 Vulkan iGPU 측정은 개발기에서 재현되지 않는다** — 실기 확보 전까지 P1 지연 수치는 "추정" 또는 실기 측정으로만 표기한다.

## 7. 알려진 한계

- 4B 번역 품질은 현행 12B 대비 미검증이며 하락 가능성이 높다. 품질 판정이 최우선 관문이다.
- 지연 2초 목표는 미달 가능성이 높다. 번역은 끝까지 수행하므로 대기열이 누적될 수 있다.
- iGPU Vulkan 성능은 보고가 엇갈린다(CPU 대비 STT 3~4배 보고 vs Intel iGPU 의 llama.cpp Vulkan 저성능 보고). 미실측.
- whisper.cpp 가 `no_speech_prob` / `avg_logprob` 을 노출하지 않으면 확률 기반 환각 필터가 비활성화되고 텍스트 임베딩 게이트만 남는다(`whisper_cpp_engine.py` docstring).
- partial 용 빠른 서버와 final 용 서버를 분리하지 않으면 `-bs 5` 가 partial 에도 적용되어 지연이 늘 수 있다.
- 노트북 서멀 스로틀링으로 장시간 세션에서 성능이 떨어질 수 있다.
- 대상 기기 실기 검증 전까지 "통과"로 선언하지 않는다(개발기 기준 통과 / 실기 미검증으로만 표기).
