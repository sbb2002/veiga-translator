# 프로파일 P2 — GTX 1050 Ti 4GB (Pascal)

> **상태: 초기 가설.** 모든 값(모델 조합, `-ngl 26`, beam, 간격)은 평가 세션에서 확정한다.
> 설계 근거: `docs/planning/HARDWARE_PROFILES.md` §4, §8. 정의 파일: `profiles/p2.yaml`.

## 대상 하드웨어

- NVIDIA GTX 1050 Ti (Pascal, sm_61), VRAM 4GB, 대역폭 112GB/s.
- FP16 이 FP32 의 1/64 이고 텐서코어가 없으므로 fp16 경로(int8_float16, Qwen3-ASR 등)는 쓰지 않는다.
- 최신 CUDA 13 / PyTorch 는 Pascal 을 지원하지 않으므로 torch 를 쓰지 않는다.

## 번들 구성

| 구분 | 구성 | 비고 |
|---|---|---|
| STT | whisper.cpp `whisper-server`, `ggml-large-v3-turbo-q5_0.bin` | `-l ja -bs 5`, 포트 8081 |
| 번역 | llama.cpp `llama-server`, `google_gemma-3-4b-it-Q4_K_M.gguf` | `-ngl 26 -c 2048 -np 1 -fa on -ctk/-ctv q8_0`, 포트 8080 |
| VAD | silero-vad ONNX (onnxruntime) | `VAD_BACKEND=onnx` |
| 환각 게이트 | MiniLM ONNX (onnxruntime) | `HALLUCINATION_GATE_BACKEND=onnx` |
| partial 주기 | 1.0초 | `PARTIAL_UPDATE_INTERVAL_S` (가설) |

## 필요 파일

- `backend/models/ggml-large-v3-turbo-q5_0.bin` (whisper.cpp 양자화 모델)
- `backend/models/google_gemma-3-4b-it-Q4_K_M.gguf` (약 2.5GB)
- `whisper-server/whisper-server.exe`: whisper.cpp 빌드. CUDA 12.x 또는 Vulkan 빌드.
- `llama-server/llama-server.exe`: llama.cpp 빌드. CUDA 12.x 또는 Vulkan 빌드.
- **빌드 요건(미검증):** 두 바이너리 모두 sm_61(Pascal) 커널을 포함해야 한다. CUDA 13 빌드는 탈락한다.
  포함 여부는 빌드 후 실행으로 확인한다.

## 설치 의존성

```
pip install -r backend/requirements-lite.txt
```

torch / transformers / sentence-transformers 는 설치하지 않는다. `faster-whisper` 는 lite 목록에 있지만
whisper-cpp 경로에서는 import 되지 않는다.

## 실행 방법

```
set LT_PROFILE=p2          (PowerShell: $env:LT_PROFILE = "p2")
start.cmd
```

런처(`tray_launcher.ps1`)가 `launch-args whisper p2` 로 whisper-server 를 먼저 숨김 창으로 띄우고,
이어서 `launch-args llama p2` 로 llama-server 를 띄운다. 로그는 `whisper_server.log`, `whisper_server.err.log` 에 남는다.
백엔드는 `uvicorn backend.main:app --port 8000` 으로 띄운다.

확인 명령:

```
python -m backend.profile validate p2
python -m backend.profile launch-args llama p2
python -m backend.profile launch-args whisper p2
```

## 평가 시 확인 항목

1. **Pascal 빌드 동작:** whisper-server·llama-server 가 GTX 1050 Ti 에서 CUDA 커널을 실행하는지(CPU 폴백이 아닌지) 로그로 확인.
2. **VRAM 피크 ≤ 4GB:** whisper-server 와 llama-server 를 합산한 피크를 측정. `llama-bench -ngl` 을 0 / 10 / 20 / 26 으로 스윕해 `-ngl` 을 확정.
3. **4B 품질 비열등성:** 기준선(gemma-3-12b Q4_K_M + Qwen3-ASR)과 L1 페어드 비교(번역 chrF++, 정성 3축).
   불합격이면 이 번들은 탈락한다(HARDWARE_PROFILES.md §8.3).
4. **대기열 드리프트:** L3 지연 재생(`LT_PROFILE_OVERLAYS=_measure` 병행)에서 final 대기열 기울기가 0 을 넘으면
   "실시간 지속 불가"로 표기한다(§8.6 판정 규칙 ②).
5. whisper-server 의 `-bs 5` 가 partial 과 final 에 모두 적용되는 영향(partial 지연 증가 여부).

## 알려진 한계

- 전 값이 가설이다. 측정 전에는 통과 여부를 선언하지 않는다.
- 요청별 `beam_size` 지원 여부 미확인. 필요 시 `WHISPER_CPP_FINAL_URL` 에 `-bs 5` 서버를 별도로 두는 방식으로 분리한다(현재 미설정).
- whisper.cpp 는 per-segment `no_speech_prob` / `avg_logprob` 노출 여부가 미확인이다.
  노출되지 않으면 임계값 필터층이 비활성이고 텍스트 기반 임베딩 게이트만 적용된다.
- Pascal 빌드 실기 검증 전에는 속도 추정이 없다. 개발기(RTX 4080 SUPER)에서 측정한 값은 상한(best case)으로만 해석한다.
- 4B 는 12B 대비 일본어→한국어 번역 품질이 낮을 가능성이 높다(일·한 직접 비교 자료 없음).
